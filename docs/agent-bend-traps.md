## Bend traps (learned here, keep adding)

- A `match` scrutinee must be a parameter or pattern-bound variable, even in a multi-match. Pass computed values (`String.eq(a, b)`) to a helper def that matches on its parameters.
- A def must be defined above its uses. Forward `law` declarations don't help: live code can't call an unfilled law.
- No mutual recursion. When a recursive walk needs a per-element decision, compute it in a non-recursive step and recurse on the tail: `go(t, step(h, st))`. For look-ahead, pass the head's precomputed flag as a parameter: `go(t, hit(t, k), k)`.
- In a recursive call the shrinking argument comes first. Arguments before it must be passed unchanged.
- Operators need a type: `(a + b : U32)`. Division too: `((x * 255 : U32) / 200 : U32)`.
- Inside `do`, only `x : T <- m`, `x : T = v`, and steps are allowed. Destructure in a helper def.
- `A & B` is affine. For a reusable pair in a `List<&2, …>`, declare a small `is Data` type (like `KV`).
- Multi-arg calls on List/Maybe take the quantity first: `List.head(&1, String, xs)`, `Maybe.default(&2, U32, m, d)`.
- `bend page.html -o dist` writes an empty chunk when a .bend file fails to check. Always `--check-only` first (`scripts/check.sh` does).
- `Nat.max`/`Nat.min` recurse once per unit: at epoch-second scale they overflow the stack. Use `Time.max` (model.bend) or `Bool.pick(Nat, Nat.is_ge(a, b), a, b)`. `Nat.add/sub/mul/div/mod/cmp/is_*` are native and safe.
- Never choose between screens, overlays or lists with `Bool.pick` or `Out.when`: every hidden screen gets laid out each frame (the thread view cost 70 ms that way). Match on the Bool in a helper (`Lay.main.k`, `Lay.proj.if`, `Proj.items.q`, `Ops.picked.k`).
- `Bool.pick(T, c, a, b)` evaluates both branches, so each variable in them counts as used twice (mark it `+`). When a branch consumes something affine, match on the Bool in a helper instead.
- A recursive call in both branches of a `Bool.pick` (`Bool.pick(L, c, h <> go(t), go(t))`) doubles the work per element: 2^n. It passes a test with a few items and hangs on real data. Match on the Bool in a helper (`Stats.prefix.k` in core/perf.bend).
- Multi-match scrutinees must follow binder order: parameters in declaration order, then pattern-bound names in binding order.
- `List.map` and `List.filter` accept only `List<&1, _>` or need `~` templates with closed arguments. For `List<&2, _>`, write the recursion.
- IO loops: a looping def passes a continuation lambda that calls itself with less fuel (`r => Helper(r, x2 => Loop(f, x2))`). The helper must never name the loop, or the two become mutually recursive.
- Put the shrinking argument first even in IO loops (`Hub.commit(cs, h, …)`, not `(h, cs, …)`).
- `where` is a keyword.
- A let (`+x = …`) may not come before a `match` on a parameter. Put the lets inside the case, or compute them in a wrapper def and pass them in.
- `++` joins Strings only. Lists join with `List.append(&2, T, a, b)`; for many, a small concat over a list of lists.
- A float literal bound by a let needs a type: `+d = {0.635 : F32}`.
- `IO.args()` gives a `List<&1, String>`; copy it into a `List<&2, String>` with a small recursion to use it more than once.
- Constructor ids of module types are path-qualified in C (`CID__HOME_..._WKEY`), so an effect cannot build them. Effects return Base types (lists of U32, strings, tuples) and Bend decodes them (`Win.decode`).
- Names Base already uses (`Event`, `App`, `Kind`) cannot be redeclared.
- `Tools`: `scripts/bend-order.py FILE` fixes def order (and reports mutual-recursion cycles); `scripts/bend-reuse.sh FILE` marks binders reported as consumed twice.
- Rewrites: `%e : P` with `e : {a == b}` turns a goal `P[_ := b]` into `P[_ := a]`. Use `Equal.sym` to flip direction and `Equal.trans` to chain.
- A destructuring let of a call (`K{a, b} = f(x)`) is a match on a computed value and is rejected. Build trees bottom-up (pair a list level by level, `Tab.up` in glb.bend) instead of returning `(tree, rest)` pairs.
- `is` is a keyword too: a parameter named `is` fails to parse. So is `def` (`+def: String` fails with a bare "Error:").
- Bits to float: `match u: case U32{w}: F32{w}` reinterprets a U32 as F32 at no cost (`Glb.f32`); `F32.bits` goes the other way.
- `IO.args()` answers `List<&1, String>`; copy it into a `List<&2, String>` by recursion before reading it twice. Under Bend 2.0.36 it starts with the program's name: programs read `src/server/argv.bend`'s `Argv.args()` (the mains go through `Rvc.main`).
- Random access into big byte lists: turn them into a balanced `Data` tree once and walk ranges (`Words.range`), never `drop` per lookup.
- A multi-match that discards a cons tail with `_` next to another scrutinee fails ("_ consumed more than once"): bind it (`case +h <> +r True{}:`).
- Only tail calls are free: a walk that builds its result outside the recursive call (`String.repeat`, `Utf8.encode_onto`, `Json.items`) overflows the stack around a few hundred thousand steps. For big inputs, push onto a reversed accumulator and reverse once (`Enc.go` in cbor.bend).
- In `win.c`, an Xlib call outside the pump (XPutImage, XFlush...) can pull input into Xlib's queue while the pump sleeps on the socket; call `win_nudge(a)` after it or keys show one keystroke late.
- "Error: an arity over 255" from a C build (never from `--check-only`) came from one expression reusing a `+` binder through nested calls (`Nui.with_ui(Hint.set(n, ""), U.Ui.scratch_set(Nui.ui(Hint.set(n, "")), …))`). Name the step in a helper (`Blur.set(Hint.set(n, ""), "1")`). Bisect with a tiny program that calls the suspect and `bend x.bend -o x.c` (C emission only, ~25 s); JS-only tests like `test/menu_test.bend` fail this way on main too, so don't bisect with them.
- Effect C must not contain the word `undefined`, even in a comment: bend reads it as a missing name and stops with "an unbound name in the emitted C" (vendored code included, e.g. stb_image in `src/app/effects/img.c`).
- `Bool.and`/`Bool.or` are strict: both sides are always computed. An `Eq.*` over a list compares all of it.
- `U32.shr(x)` shifts by one; `U32.shrn(x, n)`/`U32.shln(x, n)` take a Nat count.
- A `+n: Nat` parameter makes the `1n+k` predecessor reusable too; with a plain `n`, `k` may be used once.
- In dash (`/bin/sh`), `${d#~/}` expands the `~` first and strips nothing; use `${d#??}`.
- The glyph cache's string-keyed `Map` is slow per glyph; `Text.get` reads ASCII from the face's `GTab` (filled by `Face.tabled` once warmed).
- A long-lived native process gets slower at the same allocation-heavy work each time it repeats it, memory flat (bendlang/bend#1007: free chains lose address order; a board parse 0.2 s → 1.6 s over six runs). Keep big repeated work out of the hub: parse in a child process (`backplane --plot`, src/server/plot.bend) and keep bulky data out of hub memory (plot info tables live in files). `BACKPLANE_BENCH_RUNS=6 build/plot_bench FILE` shows it.
- "an arity over 255" at `-o` (not at `--check-only`) means a value held in the app's state flattened into too many fields: a deep record type (the board face inside the viewer's `Vx`). Put the deep part behind a `List` (`Scene3.face`). Adding a field to main.bend's `Kept` did it too (the room's wrapped posts): `park` now sits behind a one-element List.
- `Nat.read` (and `Maybe.map` over it) in anything a law normalizes makes `bend PROOF.bend` crawl for minutes. Parse digits yourself (`Switch.num` in model.bend, `Tag.num` in hub.bend), and time a new law alone before the full run.
- `.` and `_` mangle alike in C: `TL.mine.of` and `TL.mine_of` both become `..._TL_MINE_OF`, and the native build stops with "two names mangle to". `--check-only` does not catch it.
- A hub started on a copy of a real `events.jsonl` (to measure with real data) resumes every turn that was running in it as a live agent in the real folders (`Hub.recover.carry`). Run such a hub with `BACKPLANE_AGENTS=<a folder of stand-ins>` (as in `test/tools/*_e2e.ts`): a PATH without `claude` is not enough, the hub merges the login shell's PATH and `~/.local/bin` in after its own (core/clipath.bend). Run it with `--foreground` so its PID is yours.
- Launch time: nothing slow may run before the window opens (probes, network, full log copies). Start it after, in the background, and serve the last answer meanwhile (`src/core/boot.bend`). `test/native/boot_bench.bend` times start-up and frames on a real log.
- CPU forks are dealt out once, not stolen: fork over one flat balanced tree of work items (all primitives of all nodes) rather than nesting forks per group; nested forks inside a heavy group barely spread.
- The runtime deals out a value's work at the first fork it meets while evaluating it, and everything after runs where it was dealt. A spatial quadtree whose busy part sits in one corner (a thread's text) ran on one core however many there were. Collect the heavy items into a list, deal them round robin into a balanced tree (`Jobs.deal` in tiles.bend), and evaluate that tree in its own `do` binding so its forks are the first ones (main.bend's `Shell.present`). `test/native/par_bench.bend` shows each shape on 1 and 16 cores.
- Fork arguments are fine to be cheap references: the runtime's rc counts make a shared list read by many lanes cost atomics, but the balanced tree above still spread 10x.
- The phones' bundle gets native `String.cmp`/`String.eq` (`scripts/bridge-native.py`, run by `scripts/build-mobile.sh`; it stops the build if Bend's output changes shape): Bend's own compare a char at a time was over half of every phone screen. Bench the phone client with no hub: `test/tools/phone_screen_bench.ts` (screens) and `test/tools/phone_stream_bench.ts` (streamed text), `BUN_JSC_useJIT=0`, on a state from `launch_bench.ts cold`.
- Streamed text: the hub merges a read's run of Claude text deltas into one (`Delta.merge` in hub.bend) and a read that ends mid-stream waits `Delta.pace()` ms before the next, so a fast agent sends a few frames a second, not one a token (`test/delta_test.bend`); a phone builds no screen for another thread's delta (`Hubs.shows`, laws `hubs_delta_*`), and a screen the app dropped as stale is owed to the next frame (`owe` in bridge.js and both Engines). WebSockets are `TCP_NODELAY` (`sock_dup` in host.c).
- A throwaway hub on a copy of the real log resumes the turns that were running in it (a second agent in your worktree): append a `SettingSet` of `restart.continue` to `off` to the copy first.
- The phones' kept-state key (`scripts/state-key.py`) hashes only the types the kept `Hubs` value can hold (`--types` lists them); a new key makes every phone drop its state and fetch the hub's whole log, so don't change those types lightly.
- `backplane --version` prints the version and exits; any unknown argument exits 2 without starting anything (`src/core/cli.bend`). An older installed binary still starts a hub on the live home for any argument: ask a running hub's `/hello` instead.
- In the JS build (web, phones) a Bend `String` is a JS string: matching `SCon` is `codePointAt` + `slice`, and `String.eq`/`String.cmp` rebuild both strings as they go. Comparing or walking long text char by char is quadratic on QuickJS (Android). Don't compare message texts per screen; find cheaper keys or keep the walk out of the per-screen path.
- In the JS build a string grown a char at a time (`SCon{c, acc}`) is a rope: the next `codePointAt` on it copies all of it. Reading the head of an accumulator at every char (links.bend's `Link.word` did, for every char of a streamed reply) is quadratic; ask only when needed (match on the cheap test first).
- An equality over a quadtree (`Eq.image`) guarded by `Bool.and` walked the viewer's whole base at every tile level each frame, changed or not. Compare the cheap part first and the image only when it matches (`Eq.tile`), and carry the verdict down the tree (`Eq.image.go`).
- Shifting a quadtree image by a few pixels (to reuse a panned base) cost more than drawing it again: every node moves off its grid. Draw again in parallel instead.
- In JS, a Bend value is objects nested once per list cell (tens of thousands deep for a log). Anything recursive over it overflows the engine's stack: `JSON.parse` with a reviver lost the phones' kept state at every launch. bridge.js writes the state flat (`flat`/`unflat`, no recursion); time a launch with `test/tools/launch_bench.ts` (`BUN_JSC_useJIT=0`).
- Base's `String.split` recurses once per character too: `Img.paths` split every long reply that named an image that way, the phones' JS engine ran out of stack inside `recv`, and the hub's whole frame was lost (a message sent then never showed in that thread). `Img.words` cuts words in one tail-recursive walk and drops a word over `Img.long()`. Replay a real log through bridge.js under the phone's limits to find these: `BUN_JSC_useJIT=0 BUN_JSC_maxPerThreadStackUsage=4194304`.
- Base's `String.to_lower`/`to_upper` recurse once per character outside a tail call. On a long message they overflowed the phones' V8 sandbox, which crashes natively (no RangeError) and took the Android app with it. Never lower a whole message text; look at the few characters you need (`Img.may` in images.bend). Android now starts the client again in QuickJS if the sandbox dies (`Engine.eval`, `Core`'s `onReset`). Replay a phone launch on real data at a small stack to find these: `node --stack-size=500` with `test/tools/launch_bench.ts`.
- A join's chunks are split, joined, encoded and sent in C (`H.Sock.send_items`, host.c's `ji_*` over `jc_*`: the writer's `WItems` lines as `OB.Items.texts.s` frames them, JSON text straight to the same CBOR bytes as `W.Ws.cbor`, checked line by line and chunk by chunk on real logs by `test/native/cbor_frame_test.bend EVENTS.jsonl`): Bend's encoder sent a 100 MB log at ~1.5 MB/s, and measuring and joining each frame's lines in Bend cost more than encoding. Live frames still go through `Ws.cbor` (the writer counts their bytes). The hub walks the log's length only when a join's next 2000-line window is due (`Boot.k.rest`), not per 64-line chunk: per chunk it made a join quadratic.
- The hub must not read the text of log lines (`String.length`, joining, parsing) per chunk or per frame: a log line is shared, and reading a shared String's characters cost ~1 µs a character (a join's 128 KB chunk took 200 ms on the hub, and every other client waited). Count lines, hand the list to the writer (`WItems`), and let it put the frame together once (core/outbox.bend, server.bend's `Hub.boot`).
- The event loop polls sockets only when no fiber can run: a fiber that always has work (a join's chunks back to back, a reader decoding a ping flood) starves every request. Space repeated work out (`Self.post.later`) and keep per-frame work O(frame): `Ws.decode` once checked `List.length` of the whole buffer per frame (`Ws.has` now), so 20000 pings froze the hub for 7 s. `bun test/tools/stall_e2e.ts` measures both.
- The hub runs on macOS too (release target darwin-arm64: `backplane-serve` as `backplane`, no window; release.yml's `emit-darwin` emits its C and the web client on Linux, `scripts/build.sh emit`, and `build-darwin` compiles them, `BACKPLANE_PREBUILT=1`: bend's emit needs more memory than a macOS runner has). Shell it runs must not assume GNU or Linux: macOS has no `timeout` (use `Port.tmo()`'s `tmo SECS CMD` in a script, or `P.Proc.run("sh", Port.timeout([SECS, CMD, ...]))`; src/core/port.bend), no `setsid` (perl's `POSIX::setsid`), no `realpath -e`, `find -printf`, `stat -c` or `/proc`. Try a change to such a script on a Mac (`hs-mac-mini` has bend and bun; `scripts/build.sh && scripts/smoke.sh` there).
- A `Bool.pick` whose other branch parses (`Review.label`/`Review.say`: `J.Json.parse(summary)` for every act, review or not) parses every frame. Match on the condition in a helper before parsing (`View.act.spans`).
- `Bool.and(a, b)` in a recursive equality walks everything even after a mismatch. Carry the verdict as a parameter so the walk stops (`Eq.ops.go` in tiles.bend) and prove it once (`ops_go_sound`).
- Bend 2.0.36 (the pin): Base owns the constructors `Look`, `Scroll`, `Ready`, `Wait` (type `Poll`), so a type cannot declare them (ours: `DeskView`, `CatLook`, `BoardLook`, `ScrollEnd`); a def name's dot-separated parts cannot start with a digit (`Nui.key.view3`, `Ob.body.s0`); `Chan.send` answers `Result<&1, &1, T, Unit>` (not Bool); `TCP.listen(host, port)`; a JS effect twin registers each def with `io_eff(CID(Def.Name), fn)` at its end (no need argument; the function parks itself). A program that relies on foreign code (any C/JS effect) prints `SOME PROOFS FAIL` / `N defs rely on unsafe or foreign code` and exits 1 under `--check-only` and `bend PROOF.bend` even when all checks pass: scripts/check.sh accepts exactly that and nothing else.

- Bend 2.0.36's JS target keeps a `Nat` as a Number inside and hands it to JS as a BigInt, so every exported def a JS file calls walks each argument and its answer whose type holds a Nat (in, out, and the argument back). bridge.js hands the whole client state (`Hubs`, every hub's log) to every call, host.js its `Ui`: each frame (and each web keystroke) walked it several times and a phone's cold join went quadratic (a real log: 93 s with no JIT instead of 12, minutes of an empty list on an iPhone). `scripts/js-unmarshal.py TAG FILE...` makes a type's two marshallers return their value (`hubs.Hubs` in build-mobile.sh, `../core/client.Ui` wherever the web is built; the state stays in Bend's form on the JS side, and bridge.js's `unflat` loads naturals as Numbers) and stops the build if it does not find exactly two. A new export that takes or answers a big Nat-holding value from JS pays the same walk. The kept-state key hashes `bend version`, so a Bend upgrade makes every phone fetch every hub's whole log: run `bun test/tools/phone_cold_e2e.ts BINARY BRIDGE` (a cold join at the phone's stack, no JIT: no throw, flat cost per frame, the screen's iOS fields) before shipping one.
- A def the phones fold on every event must not walk the whole log outside a tail call: `Switch.count` (a `ProviderSet`) did, overflowed the phones' stack on a real log, and the frame was lost (the join never caught up). Count from the thread's `State.mine` with an accumulator.
- `--check-only` reports some errors as a bare "Error:" with no message, at the def after the cause or at a def with the same name: a def declared twice (`Bom.keep` twice in one file), a type name another module already has (`Cols` in qr.bend and bom.bend), a `let` without its type inside `do` (`+x = v` needs `+x : T = v`). Running the file (`bend test/x_test.bend`) names a duplicate ("duplicate declaration").
